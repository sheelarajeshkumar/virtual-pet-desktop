# Governance

Virtual Pet Desktop uses a maintainer-led, contribution-driven model.

## Roles

- **Users** use the project and provide feedback.
- **Contributors** submit issues, documentation, assets, code, reviews, or tests.
- **Maintainers** triage work, review contributions, manage releases, and enforce project policies.

The current lead maintainer is [@sheelarajeshkumar](https://github.com/sheelarajeshkumar).

## Decisions

Routine changes are decided through pull-request review. Significant changes—such as a pet-pack format, plugin system, storage migration, or supported-platform change—should begin with a public design issue. Maintainers seek rough consensus and make the final decision when consensus is not possible.

## Becoming a maintainer

Regular contributors may be invited after demonstrating sustained, constructive participation; sound technical and licensing judgment; reliable reviews; and alignment with the Code of Conduct.

## Project continuity

If the lead maintainer is inactive for an extended period, active maintainers should document a succession decision publicly. Repository access must follow least privilege and require two-factor authentication.
